# 128 paper-figure-explainer 設計 v0（Codex 相談前の叩き台）

2026-10-28 作成。施主の依頼:「論文を PDF やウェブで読み込ませると、図を一つずつ読み取って Fig ごとに解説する。
縦軸は何で横軸がどういう意味、この図は何を示しているか、たとえばこのピーク（黄色ハイライトや赤丸）。
動画でなく HTML スライドでもよい。とりあえず動いて解説が欲しい。図の解説で引用している文献も持ってこれるといい」。

## 1. 何を作るか（完成の定義・MVP）

ローカルで動く「論文 → 図ごとの動く解説」生成器と再生ページ。

1. 入力: 論文 PDF のパス、または URL（PDF 直リンク／`citation_pdf_url` を持つ論文ページ／arXiv）。
2. 出力: `work/<paper_id>/player.html`（単一 HTML・ブラウザで開くだけ）。図 1 枚につき数ステップの「動く解説」:
   - 図の全体 → 横軸を光らせて「横軸は温度（°C）」→ 縦軸 → 曲線の凡例 → 読みどころ（帯の黄色ハイライト・ピークに赤丸・矢印・拡大）→ まとめ。
   - 各ステップに日本語ナレーション（edge-tts の MP3・字幕つき）。自動再生と手送りの両方。
   - 図の下に「この図の根拠（本文のどの段落か・引用文）」と「この図の解釈で引用されている文献カード（題・著者・年・DOI・抄録の要約・OA リンク）」。
3. 合格線（テスト論文 = 施主の Taira 2026 JAAP、全 13 図）:
   - 図 13 枚の切り出しが正しい（本文の写り込みなし・図の欠けなし）。
   - グラフ図では、軸の意味と単位が正しく、赤丸が実際の曲線の頂点に乗る（論文本文の「DTG peaks at 353 °C and 348 °C」と ±3 °C）。
   - ナレーションの事実主張はすべて本文・キャプションの引用に紐づく（紐づかないものは画面に「[要確認]」）。
   - 図ごとに本文で引用された文献が出る（参照番号→文献リスト→DOI 解決）。

動画（mp4）化は Phase 2。プレーヤーの描画を「時刻 t から全状態が決まる」形にしておき、115 の HyperFrames 書き出しに乗せられるようにする。

## 2. 全体の流れ

```
ingest  : PDF/URL → paper.pdf, meta.json（題・著者・DOI）
layout  : ページ → 本文段落・キャプション・参考文献リスト（text.json）
figures : キャプション錨＋描画/画像の塊 → 図の領域（figures.json, fig_N.png @3x）
geometry: 図ごとにベクター解析 → 枠（plot frame）・目盛りの塊・曲線（色つき点群）・図中ラベル（geometry_N.json）
marks   : geometry の候補に番号を振った「印つき画像」（som_N.png）
analyze : LLM（claude -p・画像 Read）に som 画像＋キャプション＋本文の言及段落＋参照番号を渡し、
          構造化 JSON（軸の読み・曲線の名前・解説ステップ・根拠引用）を返させる（analysis_N.json）
resolve : 目盛りの値×位置で軸を較正 → データ座標の指示（「x=353 付近の極大」）を画素へ。曲線の実点に吸着。
          検算（本文の数値と吸着結果の差）を記録（resolved_N.json）
cite    : 言及段落の参照番号 → 文献リスト → Crossref/OpenAlex で DOI・抄録・OA リンク（refs.json）
tts     : ステップごとに edge-tts → mp3＋語の時刻（audio/）
build   : player.html（全データ埋め込み・画像は base64 か相対パス）
```

各段は冪等・ファイル契約で繋ぐ（115 と同じ流儀）。LLM は analyze だけ。座標は LLM に出させない。

## 3. 核心の設計判断

### 3.1 座標を LLM に言わせない（Set-of-Mark＋データ座標）

画像モデルは「この点は (412, 233) px」の精度が低い。そこで:
- ベクター図: PDF の描画命令から枠・目盛りの塊・曲線・図中文字の塊を機械で取る。
  実測（Taira 2026 Fig.1）: 目盛りの数字・軸題・凡例は文字ではなく**輪郭の塗り**（fill の小さな塊）。
  曲線も**色つきの塗り**（緑 = 0,0.69,0.31／橙 = 0.91,0.44,0.20、各 2000〜4600 セグメント）。枠は白の矩形＋黒の線。
- その候補に番号（T1, T2…＝目盛り、C1, C2…＝曲線、L1…＝図中ラベル）を振った画像を LLM に見せ、
  LLM は「T3 は 200、T4 は 300」「C1 は Wood の DTG、右軸」と**番号と値だけ**答える。
- 解説の指示は**データ座標**で出させる:「C1 の x=340〜365 の極小に赤丸」「x=280〜380 に黄色帯」。
  resolve が較正（最小二乗の 1 次式・対数軸の判定・残差で検査）で画素に直し、曲線の実点の極値に吸着する。
- ラスター図（埋め込み画像・スキャン）: 描画命令が無いので、①目盛り候補は OCR なしの格子（0〜1000 正規化座標の補助線入り画像）で LLM に読ませる ②曲線は色の分離で点群を作る（凡例色を LLM が答える）③吸着は色点群で。精度は落ちるので画面に「近似」の札。

### 3.2 解説の根拠は本文に縛る（捏造防止）

- 各ステップに `evidence: [{source: "caption"|"para:<id>", quote: "<原文の一部>"}]` を必須にする。
- quote が原文に実在するかを Python で照合（空白正規化後の部分一致）。無ければ step を「[要確認]」表示に落とす。
- 軸の意味の説明（「DTG は重量減少の速さ」など）は一般知識なので `kind: "background"` として許可するが、画面で色を変える。

### 3.3 図ごとの引用文献

- 本文段落 → `Fig. 3`、`Figs. 2 and 3`、`Fig. 5a`、`Figure S2` の言及を正規表現で拾い、図⇔段落の対応表を作る。
- 段落内の参照マーカー（`[12]`、`[3–5]`、上付き数字、`(Kawamoto et al., 2008)`）→ 参考文献リストの項目。
  数字型は番号で、著者年型は第一著者姓＋年で照合。
- 項目 → DOI（文献リストに DOI があればそれ、無ければ Crossref の bibliographic 検索で上位 1 件・題の類似度で検査）
  → OpenAlex で抄録（inverted index から復元）・OA の PDF リンク。キャッシュは `cache/`。
- 将来: 引用先が OA なら、その論文の該当図も切り出して並べる（Phase 3）。

### 3.4 再生ページ（HTML スライド）

- 1 図 = 1 シーン。画面左 2/3 に図、右 1/3 に字幕・根拠・文献。下にステップの点。
- 図の上に SVG オーバーレイ。動きは CSS/Web Animations（外部 CDN なし）:
  黄色ハイライト（帯が左から伸びる・multiply 合成）、赤丸（stroke-dashoffset で手書き風に描く）、
  矢印、軸の光らせ、ズーム（transform で該当領域へ寄る）、他を暗くする（spotlight）。
- 状態は `state(t)` の純関数（ステップ開始からの経過秒 → 各注記の進捗）。HyperFrames 書き出しの前提。
- 音声は mp3 を順に再生し、`timeupdate` で字幕と注記を同期。音声が無い環境では Web Speech API に退避。

### 3.5 LLM の呼び方

- `claude -p -`（サブスク・stdin）＋ `--output-format json`、画像は `--add-dir` で work を許可し Read させる。
  直列（並列は terminated になる教訓）。1 図 1 呼び出し＋必要なら検算の 2 回目。
- 出力 JSON は Python でスキーマ検査し、壊れていれば 1 回だけ「この点を直して」で再依頼。
- プロンプトは「あなたは○○システム」型にしない（claude -p が拒否する教訓）。

## 5. 段階

- Phase 1（今回）: PDF 入力・ベクター図・折れ線グラフ系を完走（Taira 2026 の Fig.1・7・8・9・10・11）。
  図式（機構図・構造式）は「拡大＋箱＋矢印」型のステップで説明（座標は箱の候補＝図中ラベルの塊から選ばせる）。
  プレーヤー・TTS・引用カードまで。
- Phase 2: URL 入力・ラスター図・mp4 書き出し（HyperFrames）・ローカルのアップロード画面（「サイト」化）。
- Phase 3: 引用先論文の図を並べる・英語ナレーション・複数論文の棚。

## 6. 懸念（Codex に聞きたいこと）

1. Set-of-Mark＋データ座標の方式で、二軸グラフ・多パネル図・クロマトグラム（ピークが多数）に破綻点はあるか。
2. 輪郭化された曲線（塗りの輪郭）から中心線を取るとき、x ビンごとの上端/下端平均で十分か。重なる曲線の分離は。
3. 図の領域検出: キャプション錨＋描画の塊の和で、2 段組・全幅図・図が別ページにあるケースを拾えるか。
4. claude -p に画像を Read させる設計の脆さ（権限・パス・出力の揺れ）。Codex（画像入力）を代替経路に持つべきか。
5. 引用の照合: 著者年型と番号型の混在、`[3–5]` の範囲展開、Crossref 誤ヒットの検出基準。
6. 「とりあえず動く」を最短で出すために削るべきものは何か。
